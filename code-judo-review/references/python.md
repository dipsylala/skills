# Python

Language-specific signals for the rules in [SKILL.md](../SKILL.md). Rule numbers refer to its Rules section.

## Idiomatic, not a smell

- A single EAFP or `hasattr` duck-typing check; the Python glossary names both as normal style.
- Standard-library uses of metaclasses and registration (`abc`, `enum`, `dataclasses`, `functools.singledispatch`), and framework registration such as route decorators.

## Type and boundary escapes (rule 5)

- `Any` where `object` would do, `typing.cast`, and `# type: ignore` without an error code or reason (mypy `ignore-without-code`; pyright `# pyright: ignore[rule]`).
- `Optional[...]` / `X | None` on values that are never `None` in practice.
- `dict[str, Any]` or tuples passed between layers → a `dataclass`, `TypedDict`, `NamedTuple`, or the model library the project already uses.
- `**kwargs` forwarded through several layers, hiding the real signature → explicit parameters; when forwarding is intended, `ParamSpec` (3.10+) or `**kwargs: Unpack[SomeTypedDict]` (3.12+).
- The same `hasattr` / `getattr` capability check repeated across call sites → a `Protocol` (3.8+), so the type checker enforces the shape.
- Bare `except:` or broad `except Exception: pass` hiding an unclear invariant → catch the specific exception and keep the `try` block small.
- Mutable default arguments that share state across calls → a `None` default, or `functools.cache` for memoization.
- Untyped code: the same dict-shape assumptions repeated in several functions signal a missing named structure.

## Branching and spaghetti (rule 2)

- `isinstance` chains repeated across call sites → a method on the types, or `functools.singledispatch` (dispatches on the first argument only). `match` (3.10+) tidies a single chain but does not remove it.
- String or boolean mode parameters (`mode="fast"`, `strict=True`) that switch behaviour deep inside a function → separate functions, an `Enum`, or at least `Literal["fast", "safe"]`.

## Wrappers and magic (rule 4)

- Custom metaclasses, `__getattr__` fallbacks, monkeypatching, and `globals()` manipulation where plain attributes or functions would do.
- Decorators missing `functools.wraps`, or typed as `Callable[..., Any]` instead of `ParamSpec` / `Concatenate` (3.10+), which loses the wrapped signature for readers and type checkers.
- Import-time network or file I/O, and registration into global mutable registries that depends on import order.

## Canonical helpers (rule 6)

- Prefer the standard library (`pathlib`, `itertools`, `functools`, `collections`, `contextlib`, `dataclasses`) and the project's existing helpers over hand-rolled equivalents.
- A growing `utils.py` signals logic that belongs in the module that owns the concept.

## Concurrency and atomicity (rule 7)

- Consecutive `await`s on independent coroutines → `asyncio.TaskGroup` (3.11+; cancels siblings on failure), or `asyncio.gather` before 3.11 or when `return_exceptions=True` is wanted.
- Blocking calls (`requests`, `time.sleep`, synchronous DB drivers) inside `async def` → an async client, `asyncio.to_thread` (3.9+), or `loop.run_in_executor`.
- `asyncio.create_task` fire-and-forget without a stored reference; the event loop holds only a weak reference, so the task can be garbage-collected mid-run → a `TaskGroup` or a held set of tasks.
- Related database writes outside one transaction or unit of work.

## File size and decomposition (rule 1)

- Logic accumulating in `__init__.py` → move it into named modules and re-export.
- Generated files exempt from rule 1: `*_pb2.py`, `*_pb2.pyi`, and `*_pb2_grpc.py` (headed "Generated by the protocol buffer compiler. DO NOT EDIT!"). Auto-generated migrations are exempt from the size limit only; review their content, since Django and Alembic expect hand edits.
